# Startup growth reliability integration

This branch starts at `fd0b8cc2965346c115f7a249538d51224268ff6f`. It changes the existing discovery and refresh pipeline. No new source is configured, no inventory is loaded at startup, and no new schedule is added.

## Changes by step

1. **Production dependencies.** Applied PR45's pinned `drizzle-orm`, `next`, and `tldts` patch bumps and matched `eslint-config-next` to `next` 16.3.6. PR45 alone failed the repository hygiene eval because it left the config at 16.3.5. No unrelated major dev upgrades were imported.
2. **Funding and activation.** PR51's headline subject parsing prevents investor and common verb mentions from becoming a company's raise. Verified announcements persist before optional news leads. Lead registration isolates and reports per-lead errors; article fetch errors appear in source receipts. News evidence records await employer-site access permission because publisher terms do not grant it. Activation uses one D1 batch for company, source, investor, queue, and registry rows. A shared ATS board owned by a different company is review-gated. Slug collisions get a stable domain-derived suffix. A failed batch leaves no partial activation; a concurrent write race is retryable.
3. **Compact reads.** PR47's optional `fields` projection covers job collection, detail, and intelligence jobs. Without `fields`, serializers and ETags use the existing paths. The projection is a smaller row payload; it does not claim a latency or yield increase. Malformed field lists fail with 400. Playwright uses a per-run repository-local D1 state and a local-only clock. Build configuration rejects that clock or state override, and the build-time flag removes the test clock from production output.

The intelligence default-byte golden was recaptured for this integration because step 5 adds `indexedCompanies`, source attempt/success ages, and the discovery pipeline version to the coverage object. The jobs list and detail goldens remain the PR47 pre-projection captures. No `fields` path changes an unprojected job row.
4. **Inert growth infrastructure.** `stage-cohort-manifest.ts` validates a caller-supplied JSONL file into an output report and never contacts a site or database. `public_page`, reachable terms, and robots allowance never imply automated access and reuse. A runnable staged row requires explicit reviewed permission evidence, scope, reviewer, time, and terms URL; provenance is preserved in the registry evidence record and D1 column. Manual and awaiting rows remain excluded. Evidence-specific Personio and Recruitee slug corroboration is used only for a permitted curated row citing the exact vendor board host. The PR40 startup company registration, sample employers, pack workflows, machine-local paths, and PR44 experimental workflow and seed examples were rejected. The current canonical ingest already handles all role families; no second ingest app was added.
5. **Conversion and recovery.** Each discovery invocation caps requests, elapsed work, page size, and candidate count. Work left after the budget is exhausted is reported as deferred without creating false failure receipts for unattempted sources. Investor source cursor advancement is atomic with its source receipt and occurs only after all page details and candidate writes succeed; a partial page replays idempotently. Candidate claims are atomic D1 leases, with stale leases reclaimed after an hour. Bounded pages reserve retry slots so fresh arrivals do not starve older work. Empty boards get a bounded periodic recheck on the existing schedule, provided permission remains valid and no active review blocks them. Failed or ambiguous board identity remains review-gated. Candidate receipts distinguish activation, recovery, review, deferral, block, and failure. Coverage reports indexed profiles separately from companies with verified-open jobs, queue age, and fleet source freshness.

## Invariants and rollout

- A board identifier by itself does not prove company identity. Review shared-board conflicts through the existing candidate review contract; inspect company domain, site-owned careers evidence, registry aliases, and prior source ownership before any narrow remediation. Do not run a bulk cleanup.
- Permission for a curated row must be a reviewed grant covering automated access and reuse. Keep its exact evidence URL, reviewer, scope, and review time. The staging CLI does not create a grant. A public page, robots allow, or terms URL is only context.
- The generated stage report is inert. To consider a future cohort, first review its rows and permission evidence, then separately authorize a bounded registry import and normal candidate review. This branch does not perform that import or activate a new external source.
- Existing directory, news, canonical refresh, and discovery schedules remain configured. This branch must be verified locally before any separate rollout decision. Do not call the live refresh endpoint to test it.
- The existing public API envelope is retained; compact projection is opt-in. Coverage adds explicit diagnostics without redefining `activeCompanies`, which counts companies with verified-open jobs.
